# Чек-лист проверок API (Swagger)
**Метод:** `POST /user` (Создание пользователя)

| Вид проверки | Что отправляю (Payload/Параметры) | Ожидаемый результат (Код + Тело) | Фактический результат (Баги) |
| :--- | :--- | :--- | :--- |
| **Позитивная** | Валидный JSON со всеми полями | 200 OK, `{"code": 200, "message": "123"}` | Совпадает |
| **Обязательные поля** | JSON без поля `username` | 400 Bad Request, сообщение об ошибке валидации | **БАГ:** 200 OK. Пользователь создается без обязательного поля, документация не совпадает с логикой бэкенда. |
| **Типы данных** | `id`: "строка" вместо `integer` | 400 Bad Request, `Input mismatch` | 500 Internal Server Error (бэк падает при парсинге) |
| **Граничные (Мин)** | `password`: 1 символ | 400 Bad Request, `Password too short` | Совпадает |
| **Граничные (Макс)**| `username`: 256 символов | 400 Bad Request | Совпадает |
| **Сайд-эффект** | `GET /user/{username}` после успешного создания | 200 OK, возвращаются отправленные данные | Совпадает, данные сохранены в БД |
