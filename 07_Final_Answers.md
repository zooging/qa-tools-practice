# Ответы на теоретическую часть (День 7)

## Часть 1. База
1. **Зачем DevTools:** Чтобы понять локализацию бага. Экран показывает только следствие. DevTools (Network, Console) показывает причину — сломался бэк (500, 400 ошибки) или фронт (200 OK, но на экране пусто из-за ошибки в JS).
2. **Вкладки DevTools:** Запросы смотрят в **Network**. Там видны заголовки, тело запроса, тело ответа, тайминги и статус-коды.
3. **DevTools vs Postman:** DevTools показывает то, что приложение *уже* отправило. Postman позволяет сформировать запрос с нуля, модифицировать любые параметры, автоматизировать отправку и протестировать API до готовности интерфейса.
4. **Переменные Postman:** Чтобы не хардкодить данные. Смена тестового стенда (dev на stage) происходит в один клик переключением окружения. Токены можно передавать между запросами автоматически.
5. **Что дает Charles:** 1) Подмена ответов (Rewrite/Map Local) и запросов на лету (Breakpoints). 2) Имитация плохого интернета (Throttle).
6. **Кто виноват (фронт/бэк):** Если в Network статус 4xx/5xx или таймаут — виноват бэк. Если ответ от бэка 200 OK, данные в JSON корректные, а интерфейс сломан или висит ошибка — виноват фронт.
7. **Зачем лезть в БД:** Интерфейс может кэшировать данные или отображать их с ошибками вычислений. БД — единственный источник истины. Если в БД заказ есть, а в админке нет — проблема в запросе админки.

## Часть 2. Разбор ситуаций
1. **Списание дважды:** Ловлю через Charles (Throttle). Замедляю интернет, жму оплату дважды. Фронт не заблокировал кнопку, ушло два POST запроса, бэк не проверил идемпотентность и списал оба. Баг и там, и там.
2. **Заказа нет в админке:** Ищу ответ создания заказа в DevTools/Network (какой id вернулся). Лезу в БД (SELECT * FROM orders WHERE id=...). Если в БД есть — баг на фронте админки. К багу приложу номер заказа, скрин ответа сервера и результат SQL-запроса.
3. **Разная цена:** Смотрю Network. Если сервер прислал 999, а фронт рисует 990 — баг фронта. Если сервер прислал 999 — иду к аналитику уточнять, какая логика расчета верная (может, скидка не применилась на бэке).
4. **Проверка 500 ошибки без стенда:** Charles Proxy. Ставлю Rewrite или Breakpoint на нужный запрос, заменяю статус-код в ответе на 500 и смотрю реакцию UI (не должно быть вечных спиннеров).
