# Баг-репорты по результатам перехвата трафика (Charles Proxy)

## Баг 1: Отсутствие обработки 500 ошибки сервером (вечный лоадер)
* **Шаги:**
  1. Запустить Charles Proxy (включить SSL Proxying).
  2. Открыть приложение, перейти к списку заказов.
  3. В Charles включить **Breakpoints** для запроса `GET /api/orders`.
  4. В приложении обновить список заказов.
  5. В Charles перехватить ответ сервера, изменить HTTP Status с `200 OK` на `500 Internal Server Error`, очистить тело ответа, нажать Execute.
* **Фактический результат:** Приложение показывает бесконечно крутящийся спиннер загрузки. Пользователь заблокирован.
* **Ожидаемый результат:** Приложение показывает заглушку "Произошла ошибка сервера, попробуйте позже" и скрывает спиннер.
* **Приложение:** Файл сессии `charles_500_error.chls`

## Баг 2: Отсутствие блокировки кнопки оплаты при медленном интернете (дублирование запросов)
* **Шаги:**
  1. В Charles включить **Throttle Settings** (пресет 3G / 512 kbps).
  2. В приложении положить товар в корзину и нажать "Оплатить".
  3. Пока идет запрос (из-за Throttle он занимает ~4 секунды), нажать кнопку "Оплатить" еще два раза.
* **Фактический результат:** Кнопка не блокируется после первого клика. В Charles (вкладка Sequence) видно три ушедших запроса `POST /payments`. Сервер обрабатывает все три.
* **Ожидаемый результат:** После первого клика кнопка "Оплатить" переходит в состояние `disabled` или показывает лоадер внутри себя. Уходит только один запрос.
